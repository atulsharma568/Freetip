## Current state (2026-11-03, per-creator fee rates)

- **Built; run migration 0054 BEFORE the deploy.** The owner can set the fee rates: a site-wide pair (default 5% platform fee and 2.75% processing charge, `/admin/fees`), an optional pair per creator (the **Fee rates** box in `/admin/creators/<id>`) and a bulk "apply to the ticked creators" in `/admin/fees` (search, filter, tick, apply or put back on the site rates, up to 500 at a time). The owner's own account `acepressure` is set to 0% and 0% by the migration (once, audited). Up to two decimals; the ceilings are 30% and 10%.
- **How it works.** `src/lib/money.ts` `splitTip(gross, rates)`, `feeLines` and `checkRates` take a pair (standard when none is given; `RULE_VERSION` is now `2026-11-03.1`). `src/lib/fee-rates.ts` reads and words rates and resolves the layers (standard, site in `site_settings`, a creator's own in `users.platform_bps_override` and `processing_bps_override`, both or neither). `createTipOrder` resolves the pair before the Razorpay order and copies it onto the order (`tip_orders.platform_bps`, `processing_bps`, written only when not the standard pair, so a standard-rate creator still tips before the migration is run). The books (`accrual.ts`), the dashboard estimates, the tips list, the CSV and the recap read the pair saved on each tip, so a change of rate never reaches an earlier tip. A pair outside the allowed range stops the posting loudly (the sweep retries). Saving is in `src/lib/fee-admin.ts` (audit rows in the same transaction: `creator.fee_rates_changed`, `site.fee_rates_changed`); the actions are in `src/app/actions/fees.ts`, owner-only (a source test checks each starts with the owner check).
- **Checked here:** type check and lint pass; `npm run build` passes (`/admin/fees` is a route); 25 new specs in `test/fee-rates.spec.ts` (money maths with a pair, reading typed percentages, the three layers, the books at no fees and at own rates, an old tip keeping its rate after changes, bulk saves and their audit rows, the migration run twice, the owner-only guard) and the money, ledger, earnings, balances, finance, creator and admin specs pass (183 in all, run without the browser server because another process held port 3300). A real bug the tests caught: the first version of the "both numbers or neither" database check let a half-set pair through (NULL passes a CHECK); fixed before it was committed.
- **Not yet seen:** the Fees page and the Fee rates box in a browser with a real owner login; a real tip at no fees through Razorpay and the books; the dashboard wording for a creator at no fees. The browser suite was not run.
- **Open for the owner:** the public pages still say "5% of every tip" (that is the standard rate); with custom rates the wording needs a decision. The earlier owner note that "the fee must stay flat" for a paid plan is now overtaken by this request; per-creator rates are private to the owner console and the creator's own dashboard. A real split by the payment provider is a separate step that waits for the provider answer (Razorpay Route, Cashfree Easy Split; PayU's split product was not researched): these rates are what it would use.

The speech route re-checks every rule from the database and speaks only the stored text, only for a message shown in the last 10 minutes.
