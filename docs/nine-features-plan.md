# Nine planned features: build plan (2026-11-01)

Made by a read-only planning pass against the code on 2026-11-01. Owner approved the order and the ten defaults below the same day. Phase 1 (polish) is built; this is phases 2 to 6. Before coding: Next.js here is 16.3.7, read `node_modules/next/dist/docs` for `after()`, route handlers and server actions. Every feature is switched per creator in `/admin/creators/<id>` (`src/lib/plans.ts`); flip `built: true` only when it ships.

## Shared foundation (do first, size S)
- `plans.ts`: replace `needsTimestamps` with a generic `needs?: FeatureKey[]`. `alertRules` works with sounds alone; media rules count only if `customAlertMedia` is on.
- Gate on the server at the point of use, never only in the UI: add `requireFeature(row, key)` to `src/lib/creator-features.ts`. Gate points: dashboard actions and pages, upload-token routes, `createTipOrder` (re-checks), tip-page props (`getCreator` must select `paid_features`), overlay, ack and speech routes. A switch turned off at play time drops the extras and plays the plain card.
- Extract the overlay route's serial lookups into `src/lib/alert-extras.ts` (pure resolver plus one query) adding `media`, `theme`, `level`, `birthday`, `voiceNote`, `highlight` to the alert JSON.
- `createTipOrder` takes positional args and has three insert branches kept for pre-migration compatibility: change to an `extras` object, insert the base row, then one `update tip_orders set ...` in the same transaction only when extras exist.
- Migrations from 0036, "safe to re-run", run BEFORE deploy, code falls back when a table is missing: 0036 media and rules, 0037 voices, 0038 fan profiles, 0039 voice notes, 0040 themes, 0041 birthday, 0042 highlights. (Built out of this order: overlay themes took 0037 and the fan identity trio took 0038 (`fan_profiles`, `fan_xp_events`, `users.birthday_message`, `tip_orders.birthday_md`), so the later features take the next free number, not the one listed here.)
- Tests: PGlite specs in `test/` (pattern `paid-features.spec.ts`); each feature gets pure-function tests and a gating test (switch off: extras absent, action refused).
- Shared media pipeline: `src/lib/media.ts` generalising `sounds.ts` (prefix-scoped `isOwnBlobUrl`, magic-byte checks for GIF/PNG/WebP/WebM, size caps, per-creator caps); upload tokens like `api/sounds/upload/route.ts`; extend `api/cron/sound-orphans` to `media/` and `voicenotes/`; admin removal like `admin/sounds`. Add a `review_state` (new, approved, removed) to the moderation list.

## Phase 2: media, rules, themes
1. **customAlertMedia (M).** `creator_media(id, creator_id, kind gif|image|webm, name, blob_url, mime, size_bytes, duration_ms, width, height, placement, enabled, created_at)`. Caps: 20 files, 40 MB per creator, image or GIF 3 MB, WebM 8 MB and 10 s. Files: `lib/media.ts`, `api/media/upload`, `actions/media.ts`, `dashboard/media/*`, `admin/media`, `AlertStage.tsx` (preload with `img.decode`/`canplaythrough`, any failure falls back to the plain card). WebM length cannot be checked cheaply on the server: check in the browser and make the overlay hard-cap playback at 10 s. Owner holds each creator's first upload for approval, later ones go live. No automatic NSFW scan in v1. Risks: copyright, adult content, storage and egress.
2. **alertRules (S).** `alert_rules(creator_id, min_paise, media_id null, sound_id null, unique(creator_id,min_paise))`. Pure `resolveRule(rules, amount)` picks the highest `min_paise` at or below the amount. The fan's own sound pick wins over the rule's sound; a voice tip keeps its no-sound rule but may show media.
3. **overlayThemes (M).** `users.overlay_theme`, `users.overlay_font`. Themes and a fixed font set live in code (`lib/overlay-themes.ts`, CSS variables, self-hosted fonts via `next/font`), no uploaded fonts. Unknown key means default. Check 1080p, 2K and vertical.

## Phase 3: fan identity (name only)
- `fan_key` = HMAC(creator_id, normalised name), per creator. No device ID (it would not work reliably and contradicts "one essential cookie"). Honest limits: same names merge, anyone can type someone else's name, a changed spelling is a new fan, anonymous tips never count.
- `fan_profiles(creator_id, fan_key, display_name, tips, total_paise, xp, first_at, last_at, unique(creator_id,fan_key))`, `fan_xp_events(tip_order_id unique, ...)`. Post XP in `afterCapture` (idempotent through the unique event row); reverse it in `reversal.ts`. 1 XP per ₹1; the alert shows "Lv N" (`fan-levels.ts`).
- **fanLevels (M)**, **fanCrm (M)** (`dashboard/fans`: sort, search, creator note, CSV, delete a fan; extend `account-close.ts`; switching on later has no history, backfill only from the 90-day window), **birthdayMessage (S-M)** (`users.birthday_message`, `tip_orders.birthday_md` day and month only, `fan_profiles.birthday_md`; fan declares optionally; matches today in IST; template with `{name}`; goes through the banned-word filter and TTS cap; self-declared, fires only on a tip that day).
- Profiles are kept 12 months after the last tip and the creator can delete a fan. **The privacy policy must say this first** (it promises names are deleted after 90 days; `retention.ts`).

## Phase 4: regionalVoices (M)
`users.tts_lang text null` (null = today's behaviour). Files: `tts-pure.ts` (widen `Prepared.language`, voice maps, script detection by Unicode block), `tts-azure.ts`, `voice-test.ts`. Languages: Tamil, Telugu, Kannada, Malayalam, Bengali, Gujarati, Marathi: verify every Azure voice name first. Limits: Marathi and Hindi share Devanagari so the creator's default decides; Roman-script messages (Tanglish etc.) are read by the English voice; Polly is Hindi and English only, so a regional message goes silent if Azure is down; same 500k monthly character cap. Gate in the speech route and in synthesis.

## Phase 5: voiceNotes (L, riskiest)
`tip_voice_notes(tip_order_id unique, creator_id, blob_url, duration_ms, size_bytes, status pending|attached|approved|rejected|removed, created_at)`, `users.voice_note_tiers jsonb`. Priced as a minimum tip by length (5, 10, 15, 20 s), so the fan still pays exactly the tip. Fan records with `MediaRecorder`, `audio-repair` makes a WAV (16 kHz mono, 20 s is about 640 KB), uploads through our own route (under the 4.5 MB function limit, rate-limited by IP hash), the server runs `parseWav` and returns an HMAC token of url, duration and expiry; `createTipOrder` verifies the token and recomputes the price. Exclusive with a sound or the TTS voice. Always creator-approved before any play, whatever `alert_mode` is; player in `MessageQueue`. Playback through an overlay-token proxy route; use a private Blob store (SDK 2.8.2 supports `access:'private'`) or unguessable names. Delete after 30 days and on account closing; unpaid uploads after 1 day (orphan cron). Risks: harassing or illegal audio stored by us (legal exposure the owner accepts), mic blocked in in-app browsers (offer a fallback), a rejected note is still paid (tips are final). Privacy policy change needed.

## Phase 6: highlightedMessages (M, last)
Priced as a minimum tip (`users.highlight_min_paise`, `highlight_seconds`), not an extra fee. `tip_orders.highlight`, `highlight_until`. A pinned card on a new `/overlay/[token]/pinned` (same pattern as supporters), shown only after approval and the banned-word filter; a newer one replaces the older. Gate in `createTipOrder`, the tip page props and the overlay. Marketing guard: no copy outside `[handle]` pages, admin and `plans.ts`; add a test that greps `src/app` (excluding `[handle]` and `admin`) and `src/components/sections` for "highlight" and "pinned" (the existing timestamps "highlights page" is excluded). Needs a community-guidelines line before use.

## Owner's defaults (accepted 2026-11-01)
First upload per creator held for approval; voice notes always creator-approved, tiers 5/10/15/20 s with creator-set minimums, kept 30 days, private store; name-only fan identity plus an optional "remember my name" in the browser (built); profiles kept 12 months and deletable by the creator; 1 XP per ₹1 and level shown on the alert; the seven languages above; highlight priced as a minimum tip and shown only on opted-in creators' tip pages; birthday self-declared, day and month only, fires only on a tip that day; formats GIF, PNG, JPG, WebP and WebM (no MP4); a switch turned off after a fan has paid plays the plain alert.
